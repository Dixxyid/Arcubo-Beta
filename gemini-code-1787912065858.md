# AI Developer Guidelines: WebAR Spatial Flashcard Project

**Kepada AI Assistant:** Jika Anda diminta untuk menulis kode, melakukan *debugging*, atau merancang fitur tambahan untuk proyek ini, Anda **wajib** mematuhi pedoman, konteks arsitektur, dan batasan (*constraints*) di bawah ini secara ketat.

## 1. Konteks Proyek (Project Context)
Ini adalah proyek aplikasi web Augmented Reality (WebAR) edukatif tanpa instalasi (*zero-install*). Aplikasi ini menggabungkan pelacakan gambar/marker (*Image Tracking*) dan pelacakan permukaan (*Markerless SLAM*) secara simultan. Tujuannya adalah memproyeksikan objek 3D benda langit edukatif dengan transisi yang mulus (*handover*) saat penanda fisik hilang dari pandangan kamera.

## 2. Tech Stack & Environment
Jangan menyarankan atau menulis kode menggunakan teknologi di luar batasan berikut kecuali diminta secara eksplisit:
* **Build Tool:** Vite (ES Modules murni, *bukan* Webpack atau bundler kuno).
* **3D Engine:** Three.js Murni (Vanilla ES6). **DILARANG** menggunakan A-Frame, React Three Fiber, atau *wrapper* deklaratif lainnya.
* **AR Engines:** 
  * Pelacakan Gambar: MindAR.
  * Pelacakan SLAM (Markerless): AlvaAR (berbasis WebAssembly).
* **UI/CSS:** CSS3 Murni (tanpa framework/Tailwind). Gaya mutlak yang digunakan adalah *Glassmorphism*.

## 3. Aturan Struktur Folder (Vite Architecture)
Pahami bahwa proyek ini menggunakan sistem *bundling* Vite. Patuhi jalur absolut file berikut dalam setiap pembuatan kode impor:
* **Semua File Statis Berat:** File `.wasm` (AlvaAR), konfigurasi kamera (`.json`), target MindAR (`.mind`), dan model 3D (`.glb`) **HANYA** boleh diletakkan di dalam folder `/public/`. 
* **Pemanggilan Aset Statis:** Gunakan referensi jalur absolut Vite bawaan, misalnya: `const wasmPath = import.meta.env.BASE_URL + 'alva/alva.wasm'`. Jangan gunakan sintaks impor `require()`.
* **Kode Sumber (Source Code):** Semua logika JavaScript harus dipisah ke dalam folder `/src/ar/`, `/src/core/`, dan `/src/ui/`. **DILARANG** menumpuk kode di satu file `main.js`.

## 4. Aturan Penulisan Three.js (Core Rendering)
* **Manajemen Memori:** Saat memuat ulang atau memusnahkan (*destroy*) model 3D, Anda wajib menyertakan kode `geometry.dispose()` dan `material.dispose()`. Kebocoran memori (*memory leak*) sangat dilarang karena ini berjalan di peramban seluler.
* **Skala & Koordinat:** Selalu asumsikan matriks koordinat berasal dari WebAssembly (seperti matriks 4x4 rata). Gunakan fungsi bawaan `matrix.fromArray()` di Three.js.
* **Lighting PBR:** Gunakan *Physically Based Rendering* secara optimal (`MeshStandardMaterial`). Selalu sediakan `DirectionalLight` dengan opsi *shadows* diaktifkan dan *AmbientLight* sebagai *fallback*.

## 5. Constraint Akademik & Literasi (Sangat Penting)
* Proyek ini digunakan untuk lingkungan akademik (FKIP Universitas Lampung).
* **DILARANG KERAS** melakukan halusinasi data (mengarang fakta) saat membuat *placeholder* JSON atau objek JavaScript untuk deskripsi planet/objek astronomi.
* Semua teks placeholder untuk deskripsi ilmiah **wajib** menggunakan terminologi astrofisika baku dan format referensi jurnal (*DOI/Peer-Reviewed format*).
* Profil Pengembang: Jika membuat komponen antarmuka "About/Tentang", kode wajib menyertakan identitas: Diki Prasetia, NPM 2113025007, FKIP UNILA, dan menunjuk ke *path* avatar secara eksplisit di `materials/pp_dev.webp`.

## 6. Format Output Kode
* Berikan kode yang modular (siap di-ekspor/impor dengan sintaks `export default class` atau fungsi modular).
* Sertakan komentar JSDoc (`/** ... */`) untuk setiap blok fungsi yang kompleks, terutama pada fungsi matriks serah terima (*Matrix Handover*) antara MindAR dan AlvaAR.
* Berikan penjelasan singkat di bawah blok kode mengenai alasan pendekatan matematis atau performa yang Anda pilih.
